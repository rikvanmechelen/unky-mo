# Testing

## Make targets

`make test`, `make test-race`, `make test-expectfail`, `make test-integration`, `make mocks` (regenerate mocks after changing an interface), `make mocks-check` (CI idempotency check).

## Mocking

Interfaces carry `//go:generate mockgen ...` directives. Generated mocks live under `<pkg>/mocks/` and are committed (contributors don't need `mockgen` installed to run tests). CI runs `make mocks` and fails if the diff isn't empty, so regenerate + commit whenever you change a mocked interface.

## Integration tests

`//go:build integration` tests spin up an isolated tmux server via `tmux -L <unique-socket>` and a fake `claude` binary (`internal/tmux/testdata/fake-claude.sh`) to exercise real session detection, PPID-chain attribution, and JSONL idle reads end-to-end. Tests live in `internal/integration/` and `internal/tmux/client_integration_test.go`. They set `SHELL=/bin/sh` on the tmux server to bypass the user's interactive-shell first-run wizards (zsh-newuser, fish config).

`fake-claude.sh` is dual-mode: launched with no args (as today's "live session" pane process) it writes the PID/JSONL files and blocks on stdin as before; invoked as `claude agents --json [--all]` it instead scans that same sessions dir and emits matching discovery JSON, since `claude.LiveSessions`/`ReadSessions` (`internal/claude/session.go`) now shell out to the real CLI's `agents --json` rather than reading the PID files directly. For that to intercept the real `claude` binary, integration tests call `putFakeClaudeOnPath(t)` (`internal/integration/claude_tmux_integration_test.go`) to symlink the script onto a temp dir as literally `claude` and prepend it to `$PATH` before any `claude.LiveSessions()` call.

## Expected-to-fail tests

Guarded by `//go:build expectfail` — encode CLAUDE.md claims that may have drifted from the code. Run with `make test-expectfail` (non-blocking in CI). A failure here means either the code or the docs need to change — do not silence these without making that decision explicit. Current drift: `config.Load()`'s missing-file branch skips `StateFilePath` and `Tickets.*` defaults (see `internal/config/config_expectfail_test.go`).

## Real-git tests

`internal/project/` tests create a fresh repo in `t.TempDir()` (`newGitRepo` helper) — they skip gracefully when `git` isn't on `$PATH`.

## exec.Commander seam

`internal/exec.Commander` is the shared seam for `exec.Command`-style side effects. Packages that shell out (currently `internal/github`) accept a `Commander` via a `NewClient(cmd)` constructor; production uses `moexec.DefaultCommander`, tests inject a gomock mock. Add new shell-out callers to this interface rather than re-introducing `exec.Command` directly.

## ops.Context testing

The domain operations the CLI and TUI share live in `internal/ops` as plain functions over a `*ops.Context`. The Context holds a `TmuxClient`, `ClaudeReader`, and `moexec.Commander` — all interfaces generated by `//go:generate mockgen` (mocks under `internal/ops/mocks/`). Tests construct a Context with gomock fakes and call `ops.LaunchSession`, `ops.CreateWorktreeAndLaunch`, etc. directly without bubbletea.

## TUI testing pattern

The TUI keeps its `tea.Cmd` closures as 5-line adapters: each one calls an `ops.*` function and maps the typed result to a `tea.Msg`. When adding a new tmux or claude call inside the TUI, either (a) extend the ops interface + adapter and regenerate mocks (`make mocks`), or (b) add a new `ops.*` function. Do not reach past the interface to the underlying `tmux` / `claude` packages from inside a `Model` method — the interface is what tests can observe.

## CLI subcommand testing

The CLI's subcommands (`cmd/mo/*.go`) follow the same pattern: each `RunE` builds a `*ops.Context` via `ops.NewContext(tmuxClient)` and calls an `ops.*` function. Adding a new subcommand for an existing op takes ~30 lines of cobra boilerplate.

## Sidebar testing

`internal/tui/sidebar/` keeps its own smaller `TmuxClient` / `ClaudeReader` interfaces in `sidebar/deps.go` since the sidebar runs in a separate process and reaches for a different subset (`BreakPane`, `JoinPane*`, `ActiveShellsForSession`, `FormatShellCommand`). These are generated separately into `sidebar/mocks/`. The sidebar also has a `WindowResolver` interface so tests can bypass the `$TMUX_PANE` + `tmux display-message` lookups; construct via `sidebar.NewModelWithDeps(...)` in tests. Real-tmux sidebar integration tests live next to the model under `//go:build integration` and reuse the isolated-socket pattern from `internal/integration/`.

Sidebar bug regression tests gated by `//go:build sidebarregression` live in `internal/tui/sidebar/regression_todo_test.go` and document known gaps (e.g. `refreshSyncStatus` not surviving window renames). Fixed bugs move their tests into the default-build `regression_test.go`.

## Web dashboard testing

`internal/web/` (`mo web`) follows the same scoped-interface pattern as `ops.Context`: `StateReader`, `ProjectLister`, `WorktreeReader`, `PRClient`, `TicketSource`, `PromptSender`, `SessionHistory`, `SessionOps`, `GitFiles`, `Terminals`, `Shells`, `ClaudePane`, `Subagents`, `SlashCommands`, `Restarter` in `deps.go`, generated into `internal/web/mocks/`. Handlers are tested with `httptest.NewRecorder()` (or `httptest.NewServer` + a real streaming client for SSE endpoints) against gomock fakes — no real file IO, git, `gh`, or Jira calls in unit tests. Session launch/stop handlers (`handlers_sessions_test.go`) assert *which* `SessionOps` call each request reaches. A test that expects no tmux side effect (e.g. resuming an already-live session) simply sets no `SessionOps` expectations, and gomock fails it on any call. The `NoSwitch` param on the underlying ops is covered in `internal/ops/noswitch_test.go` the same way: it leaves out the `SwitchToWindow` expectation. `handlers_log_test.go` checks that `/log` takes the checkout from the state row, caches per scope, answers a matching `If-None-Match` with 304 and rejects unknown scopes, and that the commit endpoints map `ErrUnknownCommit`/`ErrNotInCommit` to 404. `internal/gitfiles/log_test.go` runs `GetLog`/`GetCommit`/`GetCommitFile` against real git (branch vs all scope, unpushed with and without an upstream via a bare remote, renames, root commits) and checks that refs, abbreviations, options, unknown ids and tree ids are all refused as commits. `handlers_files_test.go` checks that the Files panel endpoints take the checkout path from the state row and dedupe polls through the cache (`.Times(1)` across two requests). `handlers_terminals_test.go` asserts that a pane outside the window's `Terminals.List` result (e.g. Claude's own pane) gets 404 on output/input/interrupt with no `Terminals` call. The tmux side (`ListSessionPanes`, `NewWindowInSession`, `CapturePane`, `WindowOption`) has `//go:build integration` tests in `internal/tmux/terms_integration_test.go`; tests that type into a shell set the isolated server's `default-shell` to `/bin/sh`, since `newTestClient` doesn't, and the host's zsh/fish first-run wizards would otherwise eat the input. Sidebar tests that call `refreshTerminals`/`refreshState` without testing terminals use `allowTermDiscovery(tmux)` (`drawer_test.go`); adoption and publishing tests set exact expectations instead. `handlers_restart_test.go` checks that only a POST reaches `Restarter.Restart` (202; `notify.ErrTUINotRunning` → 503) and that `/api/boot` is stable per server and new per process. `handlers_subagents_test.go` checks that the listing never exposes transcript paths and that a transcript stream only opens for an agent id the listing returned. `handlers_commands_test.go` checks that the command list is read for the state row's checkout and session, cached across fetches, and 404s with no `SlashCommands` call for a window without a session. `internal/claude/commands_test.go` covers multi-line `skill_listing` parsing, frontmatter, and the merge order on a temp `$HOME` + repo: built-ins can't be shadowed, a listed skill picks up its file's argument hint, `user-invocable: false` is skipped, parent `.claude` dirs count only up to the repo root. `internal/claude/subagents_test.go` covers the running/waiting/done/killed rules on synthetic transcripts under a temp `$HOME`, including incremental reads and partial trailing lines. `handlers_editor_test.go` checks that `/file` reads only paths in the tree or changes list (`.env`, traversal and absolute paths get 404 with no `ReadFile`/`ReadHEAD` call), maps `gitfiles.ErrOutsideRoot` to 403 and answers a matching `If-None-Match` with an empty 304. The save tests check the same refusals for `PUT /file`, plus a 409 whose body carries the current version and a 413 for an oversized body. `static_test.go` checks the embedded files' ETag revalidation and that the gzipped bundle decodes to the plain one. `internal/gitfiles/content_test.go` tests `Resolve` against real symlinks in `t.TempDir()`: links to a file outside, through a symlinked dir, a missing file under an outside dir, and inside links to `.env` or `.git/hooks` (refused too, for writes as well). It also tests `ReadHEAD` against real git, including that a git failure is an error and not "missing from HEAD". `WriteFile` is tested on a temp dir too: it keeps the mode and leaves no temp file, a stale base hash gives a `ConflictError` and leaves the file untouched, and it never writes through a symlink out of the checkout or creates a missing file. `internal/gitfiles` itself is tested on fixture `-z` bytes plus a real-git repo in `t.TempDir()` (skipped without git). The `ttlCache` backing the PR/ticket caches takes an injectable `now func() time.Time` so TTL-expiry tests don't need real `time.Sleep`.

The chat view's `transcriptCursor` (JSONL tailing) is tested against synthetic in-test fixtures written to `t.TempDir()` — no dependency on real `~/.claude` data — covering filtering, partial-trailing-line buffering, and truncation recovery. `transcriptHub` lifecycle tests use a real temp file plus the real `status.Watcher` (fsnotify), not mocks, mirroring the project's general preference for exercising real mechanisms over faking them when the real thing is cheap to set up. `SendLiteralText` (the literal-mode `tmux send-keys` used for prompt injection) gets a real `//go:build integration` test rather than a unit test of argument construction — the entire point of the method is a safety property (literal mode actually suppressing tmux's key-name interpretation for input like `"Up"`), which only a real tmux exercise can verify. `SendPastedText` has one too (`TestIntegrationSendPastedTextBracketsThePaste`): a pane that switches on bracketed-paste mode runs `cat -v`, and the test checks that the text arrived inside `ESC[200~ … ESC[201~` followed by Enter, and that no buffer was left behind. `TestIntegrationSendPromptPastesPathsThenText` does the same for `SendPrompt`: one bracketed paste per image path, then the text with a leading space, then a single Enter. `attachments_test.go` runs `AttachmentStore` on `t.TempDir()`: content sniffing (text, HTML and SVG are refused whatever they're called), the size cap, `Path` refusing traversal, absolute paths, malformed ids and another window's ids, and `Sweep` with an injected `now`. `handlers_prompt_test.go` checks that attachment ids reach `SendPrompt` as resolved paths in order, and that an unknown id is a 400 with no `PromptSender` call. No tmux integration harness applies to the rest of `internal/web` — it otherwise never touches tmux, `ops.Context`, or the hook socket.

## View() testing

Full render paths (`View()` / `Update()` end-to-end with the `bubbles/v2/list` component) are still not unit-tested — they require a list.Model populated from a slice of `list.Item`, which is expensive to set up. For those, keep extracting pure helpers (see `applyNotifOverrides` for the pattern) and test the helper rather than the whole Update branch. `internal/tui/helpers_test.go` + `internal/tui/sidebar/helpers_test.go` cover the already-extracted pure functions (status ranking, window-name parsing, file-tree rendering, etc.).
